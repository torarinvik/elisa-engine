# Cached skin-region plane measurements (in development)

Eight regions belong to each instance, each containing 1–4096 unique mesh-local
vertex IDs for one placement. Setup validates the complete region before
replacement, including allocation failure; duplicate IDs reject rather than
biasing the centroid. Instance destruction and cooked/snapshot mesh replacement
clear the regions.

`read_skin_contact` holds one owner-thread scene lock across the entire reduction
and uses fixed 64-sample stack buffers without allocating. It returns the minimum
signed distance to `dot(unit world normal, world point) + offset`, the matching
model/world vertex, the selected region centroid and vertex count. Cached render
bone buffers are not used, so post-sample pose overrides are immediately visible.
Any failed read leaves output untouched. Active morphs still reject explicitly.

The model/world lowest points identify the same vertex. The whole-foot centroid
is not a support patch. This API does not classify planted/flight state, suppress
sliding or solve IK. Matrix palettes are currently recomputed per batch/influence;
performance profiling and palette reuse remain required.

Native syntax and module hygiene pass. A fresh linked integration build and native tests pass for
four-vertex region minimum/centroid agreement, immediate pose override and failed
replacement retention on both cooked fighters. Evidence is game
`build/skin-contact-native-validation.json` and `build/skin-contact-native-build.log`. Whole-foot and multiple-batch tests remain
required before gameplay integration.

A 130-vertex region test passes across three batches on both fighters. Complete
fingerprinted weighted foot regions (black 1889/1871, white 1930/2012 vertices)
also pass cached minimum/centroid comparison against exhaustive direct reads
within 0.02 mm across four blend/interruption phases and horizontal/tilted world
planes. Animation progress remains unchanged. Evidence is game
`build/full-foot-contact-test/validation.json` and native logs. The fixture is
reproducibly generated by `tools/build_full_foot_contact_test.py` from cooked
package fingerprints; generated source belongs in game build output.

These tests compare CPU bridge reductions, not GPU skin output. Cache lifecycle
rejection probes and performance/palette reuse remain pending before gameplay
contact integration.
