# FBX polygon material subsets

**Date:** 2026-09-23  
**Scope:** Preserve FBX polygon material assignments, supported PBR factors, and a bounded set of external material images in Elisa's existing cooked geometry and snapshot material paths.

## Behavior

The bounded ufbx importer reads each face's material slot, groups triangles by slot, and emits an ordered subset partition. It accepts at most 16 slots and rejects invalid face assignments. Tangent generation and vertex-fetch remapping preserve the partition. Vertex-cache optimization runs per subset, and static-mesh simplification allocates its triangle budget across subsets and simplifies each slot independently; the budget must retain at least one triangle per non-empty subset. Skin simplification remains rejected.

The cooker writes the existing subset fields plus each authored slot's 48-byte factor record and a length-prefixed UTF-8 material name. The importer maps diffuse/base color and factor, metallic, roughness (including ufbx's Phong conversion), emissive color and factor, transparency to alpha/blend mode, and the double-sided feature. For base-color PNGs with inspectable 8-bit gray-alpha or RGBA channels, binary alpha samples infer mask mode with the existing 0.5 cutoff; intermediate samples infer blend mode. Scalar transparency that already selected blend is preserved. Other PNG alpha encodings conservatively use blend when transparency is signaled; JPEG and KTX2 alpha policy is not inferred yet. Direct external file maps for base color, normal, emissive, and ambient occlusion are translated into the runtime's five image slots. Separate roughness and metalness maps are accepted as direct external PNG files and packed into one RGBA8 surface image: R=occlusion (255, neutral), G=roughness, B=metalness, A=reflectance (255). Source maps use their red channel; a missing map fills its channel with 255. If both maps are present, their dimensions must match. A material cannot combine a prepacked surface image with either separate map. The Python cooker resolves paths under the FBX source directory, rejects traversal and symlink escapes, validates bounded image headers, and embeds runtime images in the mesh's `.elpk`; plain `.pkg` output is refused when it would lose images. Separate surface maps require PNG, mesh UVs, default UV selection, no UV transform, repeat wrapping, and external files. Layered/procedural/shader or embedded images and unsupported sampler/UV settings fail explicitly. The production geometry reader validates factor bounds, name count, UTF-8, NULs, and the 256-byte name limit. RenderScene's existing `register_snapshot_mesh_material`, `register_snapshot_mesh_material_set`, and mesh-texture registration APIs turn cooked factors and images into ordinary snapshot assets; applications still choose IDs and bind the set to rows.

Projects that bind images through another Elisa asset path may explicitly pass `--ignore-material-textures`. This retains supported scalar factors and emits no FBX image paths or package sections; the cooker does not open those paths. Default imports continue to resolve and package supported external files while rejecting unsupported roles and material graphs.

The importer does not yet create a complete node-preserving multi-mesh scene package or expose slot names through the RenderScene C ABI. Alpha inference is limited to base-color PNG data and cannot identify authored cutout intent in ambiguous images; JPEG and KTX2 alpha modes need explicit metadata support. Separate roughness/metalness JPEG decoding and non-default sampler/UV settings remain unsupported. Material-factor coverage uses deterministic Phong and 3ds Max PBR fixtures; other FBX material dialects need representative parity fixtures before the importer can claim broad material equivalence.
