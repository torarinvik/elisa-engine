# Character course package

Queue item 3 asks for a packaged app of a second, independent game. The app must
say which build it is, and a broken shipped resource must be named instead of
failing silently. The maze was already packaged (`wicked-abi-consistency.md`).
`examples/character_course` is the second game: a procedural physics course with
no cooked assets.

## Project changes

- `package.resources: []` is now valid. It declares a game with no runtime
  resource files. Only the executable, shaders and notices are staged.
  Previously the packager required an `assets` directory.
- `examples/character_course/third_party/notices/` is generated by
  `scripts/collect_dependency_notices.py`. It is byte-identical to the maze's
  notices (same Wicked/SDL3/Homebrew runtime closure), and the manifest lists
  every file.

## Build identity

`package_macos_app.py` writes one stderr line from the bundle launcher before
`exec`:

```
Elisa package: CourseValidation 0.1.0 (org.elisa.elisa-character-course) executable-sha256=888dbba0… source=e87a5bfa…-dirty
```

`executable-sha256` is the hash of the built executable before it is copied and
re-signed. `source` is `git rev-parse HEAD` of the project, with `-dirty` when
`git status --porcelain -- <project>` is non-empty, or `unknown` outside git. A
bug report that includes the first line of stderr identifies the exact build.

## Failing-resource diagnostics

Shader manifest validation used to return only a boolean. Now
`shader_manifest_failure` (in `native/shader_manifest_validation.h`) and
`manifest_failure` (in `native/shader_path_validation.h`) return a reason, and
`initialize` prints it:

- `Elisa shader manifest rejected: <reason>`
- `Elisa shader root rejected: <root> has no compiled <backend> shaders`

The reasons name the offending file where there is one: missing shader, size or
sha256 mismatch, unlisted shader, invalid entry, manifest missing, outside the
root or too large, fingerprint mismatch, or backend list mismatch.
`test/shader_manifest_validation_native.cpp` checks the unlisted, mismatch,
missing and absent-manifest messages (return codes 11–14).

## Commands

```bash
python3 scripts/elisa_build_run.py build --project examples/character_course \
  --main self_test_main.elisa --output build/character-course-selftest --optimize
python3 scripts/package_macos_app.py --project examples/character_course \
  --executable examples/character_course/build/character-course-selftest \
  --name CourseValidation --output build/CourseValidation.app \
  --shader-root ../amazing-labyrinth-wickedengine/build-elisa-sdl3/WickedEngine/shaders
python3 scripts/validate_standalone_macos_app.py --app build/CourseValidation.app --runs 2
```

## Gaps

- **Clean machine:** runs were on the development machine with source and
  Homebrew reads denied. A different, clean Mac has not been tested.
- **Signing:** only ad-hoc signing is used. Release signing and notarization are
  not done.
- **Manual play:** the packaged executable is the finite self-test. Interactive
  play of `examples/character_course/main.elisa` by a person is still open.
